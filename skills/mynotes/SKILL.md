# MyNotes 个人学习笔记

## 目标仓库与位置

- 仓库地址：https://github.com/hmljy2020/MyNotes
- Git 克隆地址：https://github.com/hmljy2020/MyNotes.git
- 仓库为公开仓库，主要存储工作中学到的知识，内容主要来自与 AI 对话后的总结。
- 所有笔记使用 Markdown（`.md`），以中文为主，平铺在仓库的 `notes/` 目录中，暂不创建分类子目录。
- `README.md` 和 `AGENTS.md` 保留在仓库根目录。Skill 文件属于工具配置，不属于学习笔记。

## 整理笔记

根据用户提供的对话、实践记录和上下文提炼内容，每篇笔记聚焦一个主题，采用清晰、便于检索的文件名。

笔记必须包含以下内容，并遵守顺序：

1. 标题后记录日期，格式为 `日期：YYYY-MM-DD`。使用实际记录日期；整理既有笔记时保留其原有记录日期。日期不明确时向用户确认，不要编造。
2. 首先描述遇到的问题。背景可以简洁，但必须完整交代问题产生的场景、想完成的事情以及遇到的困难，让读者明白为什么会有这个问题，不能直接抛出一个看上去凭空产生的问题。
3. 然后描述针对这个问题，我学到的解决方法和相关知识，包括自己的理解、适用条件和实践收获。保持问题与所学内容之间的联系。

整体采用个人笔记的风格，以“我”的经历、理解与思考串联内容。可以整理和润色已有事实，但不要编造个人经历、背景或验证结果。材料不足以交代问题来由时，先询问必要信息。

审视 AI 对话中的说法，必要时附上参考来源；区分已经验证的结论与尚未验证的推断。不要把对话原文直接堆成笔记。公开保存前，检查所用材料，避免将凭据或工作中的非公开信息带入公开仓库；如发现此类内容，先脱敏或与用户确认可公开的范围。

推荐结构如下，可根据内容调整标题和展开方式，但必须保留日期及先问题、后所学的顺序：

```markdown
# 笔记标题

日期：YYYY-MM-DD

## 遇到的问题

我在什么场景下想完成什么事情，遇到了什么困难，为什么需要解决这个问题。

## 学到的解决方法与知识

针对这个问题，我学到了什么方法、它为什么适用，以及我对相关知识的理解。
```

## 保存与仓库更新

- 用户只要求草稿时，直接给出笔记草稿；Skill 的启用本身不代表获准发布。
- 用户要求保存到 MyNotes 时，优先使用已有的对应仓库检出；没有时克隆到合适的工作目录，不依赖固定的本地路径。
- 编辑前阅读仓库最新的 `AGENTS.md` 和 `README.md`，结合用户当前要求执行。检查工作区和已有笔记，避免覆盖用户改动或重复创建同主题笔记。
- 新建文件写入 `notes/`，修改已有笔记时保留准确的原始背景与日期。检查日期、问题背景、所学内容、个人笔记语气及 Markdown 格式。
- 用户要求更新远程仓库时，提交并推送本次任务涉及的文件，不夹带无关修改。不强制推送；遇到认证、权限或冲突问题时，保留已完成内容并说明具体阻碍。
- 完成后给出笔记路径；已推送时提供 GitHub 文件链接，未推送时明确说明状态。
